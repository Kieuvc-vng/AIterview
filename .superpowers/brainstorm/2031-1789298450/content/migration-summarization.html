3 Section Cuối — Migration · Summarization · Model Config

🔄 Section 1: Migration Plan (Schema cũ → mới)

Hiện tại:

  • 4 bảng: sessions, messages, session_states, rubrics
  • 1 session = 1 job + 1 candidate (lặp lại job info nếu có nhiều ứng viên)

Sau migration:

  • 5 bảng: jobs, candidates, interviews, messages, summaries
  • 1 job dùng lại nhiều lần, messages & summaries dùng chung interview_id

Quá trình Migration:

  1. Bước 1: Tạo bảng mới (jobs, candidates, interviews, summaries)
  2. Bước 2: Migrate data từ sessions cũ
    • Group by (job_title, level, company) → tạo JOBS records
    • Extract candidate_name từ mỗi session → tạo CANDIDATES records
    • Rename sessions → interviews (cập nhật FK: job_id, candidate_id)
  3. Bước 3: Migrate messages (chỉ rename FK: session_id → interview_id)
  4. Bước 4: Archive/xóa rubrics (không dùng nữa)
  5. Bước 5: Test: queries cũ vẫn chạy được qua VIEW hoặc migration function

⚠️ Lưu ý: Nếu có data cũ trong production, cần backup trước. Nếu muốn giữ audit trail, có thể archive sessions table thay vì xóa.

🤖 Section 2: Summarization Logic (AI tóm tắt)

Cơ chế tóm tắt:

Khi nào tóm tắt?

Sau khi ứng viên trả lời mỗi câu hỏi (hoặc follow-up cuối cùng)

Input cho AI:

  • Question text (ví dụ: "Python experience?")
  • Tất cả tin nhắn liên quan (câu trả lời chính + follow-ups)
  • System prompt: "Tóm tắt câu trả lời thành 1-2 dòng, giữ lại ý chính"

Output:

  • main_answer_summary — tóm tắt câu chính
  • followup_summary — tóm tắt follow-up (nếu có)

Ví dụ:

Q: "Python experience?"
A: "Làm Python 5 năm... backend Django... blah blah..."
Follow-up: "Async/await?"
A: "Có dùng async/await... race condition... blah blah..."

→ main_answer_summary: "5 years Python, Django backend"
→ followup_summary: "Used async/await, handled race conditions"

✅ Service mới: summaryGenerator.js — call AI model để tóm tắt, lưu vào SUMMARIES table

⚙️ Section 3: Model Configuration

Theo plan, bạn cần:

Phase Model Config
Phase 1: Setup 1 model chính SETUP_MODEL (generate questions, suggest skills)
Phase 2: Interview 1 chính + 1 backup INTERVIEW_MODEL + INTERVIEW_MODEL_BACKUP
Phase 3: Summarization 1 chính + 1 backup SUMMARY_MODEL + SUMMARY_MODEL_BACKUP

.env Config (Template):

# Setup Phase
SETUP_MODEL=your_model_here

# Interview Phase
INTERVIEW_MODEL=your_model_here
INTERVIEW_MODEL_BACKUP=your_backup_model_here

# Summarization Phase
SUMMARY_MODEL=your_model_here
SUMMARY_MODEL_BACKUP=your_backup_model_here

Client Implementation:

Phase 1: callQwen(messages, systemPrompt, {model: process.env.SETUP_MODEL})
Phase 2: callQwen(messages, systemPrompt, {model: process.env.INTERVIEW_MODEL, backup: process.env.INTERVIEW_MODEL_BACKUP})
Phase 3: callQwen(messages, systemPrompt, {model: process.env.SUMMARY_MODEL, backup: process.env.SUMMARY_MODEL_BACKUP})

✅ Cách làm: Mình sẽ code để phần config Model được để trống, sẵn sàng cho bạn điền LLM API key + model name khi bạn quyết định. Không hardcode, flexible swap sau.
